# Этап A — границы реализации

Этап A из раздела 34 ТЗ является **внутренним техническим этапом**, а не публичной версией. Его задача — создать основу, на которой можно безопасно реализовывать этапы B–H без переписывания аккаунтов, прав и изоляции пространств.

## Реализовано

| Требование Этапа A           | Результат                                                                                                             |
| ---------------------------- | --------------------------------------------------------------------------------------------------------------------- |
| Репозиторий и стандарты кода | npm workspaces, TypeScript strict, Prettier, общие контракты, разделение `apps/api`, `apps/web`, `packages/contracts` |
| Next.js и NestJS             | Next.js 15 App Router; отдельный NestJS 11 с глобальным префиксом `/api`                                              |
| PostgreSQL                   | SQL-миграция `001_init.sql`, production-драйвер `pg`; embedded PGlite только для превью/тестов                        |
| Аккаунты, пространства, роли | Приглашения, вход, сессии, сеть/домохозяйство/личное пространство, 7 ролей, membership и служебные разрешения         |
| RU/IT                        | Полный словарь интерфейса, переключение языка, сохранение языка в профиле, `html[lang]`                               |
| Базовая тема и навигация     | Три темы, светлый/тёмный режим, боковое меню, каталог, поиск, избранное, быстрые действия, мобильная навигация        |
| Аудит и логи                 | Структурированный JSON-logger с редактированием секретов; hash-chained audit events; проверка целостности             |
| Тестовая инфраструктура      | Vitest для контрактов, Jest + Supertest + embedded PostgreSQL для API/E2E, TypeScript typecheck для web               |
| Деплой и восстановление      | Docker Compose, versioned release archive, SFTP upload, `pg_dump`/`pg_restore`, checksum, rollback procedure          |

## Дополнительно заложено в основу

- Публичный сайт с явно опубликованными записями и запретом закрытых маршрутов в `robots.txt`.
- Панель виджетов с изменением порядка и состава.
- Админ-панель пользователей, пространств, модулей и аудита.
- CSRF, rate limiting, блокировка после повторных неудачных входов, список/отзыв сессий.
- PWA-манифест, offline-индикатор и явное сообщение о невозможности сохранить данные без сети.
- Доступность: skip-link, видимый фокус, `aria-*`, семантические таблицы, клавиатурные элементы, крупный текст, высокая контрастность, уменьшение анимации, адаптивные режимы.

## Не входит в Этап A

Этапы B–H и перечисленные ниже подсистемы не считаются реализованными:

- CalDAV, повторяющиеся события, задачи, Kanban, shopping и уведомления;
- messenger, WebRTC/TURN, семейная лента, Yjs и совместное редактирование;
- файловое хранилище, WebDAV, галерея, OCR, поиск по содержимому;
- кулинария, финансы, дом, путешествия, погода, энергия;
- школа, медицина, защищённый сейф, родительские политики во всех модулях;
- Polza.ai, AI-память, агентские действия, realtime-голос;
- OAuth, публичные API-токены, webhooks, self-hosted аналитика;
- SMTP/Telegram/Web Push доставка, TOTP/2FA, passkeys, резервные коды;
- внешние workers, очереди Redis/BullMQ, S3/WebDAV, видео- и фотообработка;
- полные E2E-браузерные, нагрузочные, миграционные, backup-restore и доступностные автоматизированные тесты.

Таблицы `passkey_credentials`, `backup_codes`, `email_tokens` и поля политик сессий подготовлены, но пользовательские flows для passkeys/2FA ещё не включены. Отсутствие этих возможностей задокументировано, а не замаскировано демонстрационным интерфейсом.

## Definition of Done

Для модулей Этапа A выполнены серверные проверки прав, обработка ошибок/пустых состояний, журналирование важных действий, тесты, RU/IT, адаптивная верстка, базовые требования доступности и документация. Полный экспорт/backup всех будущих модулей, нагрузочные тесты WebRTC/realtime и юридическая проверка относятся к версии 1.0 и остаются открытыми.

**Вывод:** фундамент готов к Этапу B, но не готов к публичному семейному запуску с реальными незаменимыми данными.
