# Этап D — файлы и память семьи

Внутренняя техническая сборка **Этапа D** по разделу 34 [ТЗ](TZ-original.md) поверх этапов A–C. Это **не публичная версия 1.0**.

## Реализованный объём

| Пункт ТЗ                       | Реализация                                                                                                                                                                                                                                                                                                                                                                                                     |
| ------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Файловое хранилище (§7)        | Папки; загрузка частями (4 МБ, возобновляемая, идемпотентные повторы чанков); скачивание с HTTP Range; переименование/перемещение; массовые операции (перенос, корзина, теги); версии с восстановлением; корзина с восстановлением папки целиком и автоочисткой через N дней; квоты пространства и пользователя; история действий; предпросмотр изображений/видео/аудио/PDF/текста/офисных документов (текст). |
| Безопасность загрузок (§7)     | Тип определяется по содержимому (magic bytes), а не по имени: исполняемые файлы (PE/ELF/Mach-O), скрипты (`#!`) и опасные расширения отклоняются; медиа с «чужим» содержимым (переименованный бинарник `.jpg`) отклоняется; SVG/HTML никогда не отдаются inline; inline-ответы получают `CSP: sandbox` и `nosniff`. Автоматической распаковки на сервере нет.                                                                                                                                                                                    |
| WebDAV (§7)                    | `/api/webdav/<spaceId>/` — PROPFIND (Depth 0/1), GET/HEAD, PUT (новая версия при перезаписи), DELETE (в корзину), MKCOL, MOVE, COPY, LOCK/UNLOCK (рекомендательные), PROPPATCH. Аутентификация — токены устройства (HTTP Basic, пароль = токен), привязанные к одному пространству; права проверяются при каждом запросе, токен можно отозвать.                                                                |

Видео отдаётся по Range; анализ — необязательный `VIDEO_PROBE_COMMAND` (ffprobe). Очередь можно вынести на отдельный worker с тем же образом API.                                                                                          |

До включения — ручные отметки.                                                                                                 |

## Права по ролям

- Владелец/администратор — полный доступ к файлам, галерее, поиску, энциклопедии; администратор публикует и экспортирует.
- Взрослый — читает, создаёт и меняет; удаляет **свои** загрузки (в корзину), окончательное удаление — у ролей с `files:delete`.
- Ребёнок — дневник и воспоминания (`coreMember`), фото и поиск (`coreRead`): смотрит семейную галерею, комментирует и ставит реакции; файлового хранилища и энциклопедии нет; создавать внешние ссылки, публиковать, включать распознавание лиц — нельзя.
- Гость — только явно расшаренное; внешний доступ к фото — защищённые ссылки.

## Эксплуатация

- `STORAGE_DIR` (по умолчанию `apps/api/.data/storage`) должен входить в резервную копию: `scripts/backup.sh` теперь архивирует его вместе с дампом БД (переопределяется `FILES_DIR`). **Локальный диск — не резервная копия.**
- Квоты по умолчанию: 20 ГБ на пространство, 10 ГБ на пользователя, файл до 4 ГБ; меняются в `.env` и через `PUT /api/files/quota`.
- Необязательные движки задаются командами без shell, `{input}` заменяется путём к файлу: `ANTIVIRUS_COMMAND`, `OCR_COMMAND`, `VIDEO_PROBE_COMMAND`, `FACE_ENGINE_COMMAND`. Без них очередь честно помечает задачи как `skipped`, а файлы — «тип проверен, антивирус не подключён».
- WebDAV-клиенты подключаются к `https://<домен>/api/webdav/<spaceId>/` (через тот же Next.js rewrite, что и `/api`).

## Известные границы

- S3-совместимый адаптер не реализован (интерфейс готов).
- Миниатюры не генерируются: галерея показывает исходные изображения с `loading="lazy"`; для HEIC/AVIF предпросмотр зависит от браузера.
- Умный поиск по объектам и сценам и распознавание лиц требуют локальных движков; адаптер распознавания лиц — заготовка без модели. Поиск похожих (не идентичных) фото не реализован.
- PDF: извлекается только текстовый слой; сканы без текста требуют OCR-движка с поддержкой PDF.
- Поиск — `ILIKE` по полям без полнотекстовых индексов; для больших архивов нужен `tsvector`/внешний индекс.
- WebDAV LOCK — рекомендательный; конфликты разрешаются версиями. Копирование папок через WebDAV не поддерживается.
- «Запрет скачивания» в ссылках — сдерживающая мера (inline-показ, без `attachment`), а не DRM.
- Вложения мессенджера Stage C по-прежнему хранят метаданные; связь с файловым модулем — следующий шаг.
- Браузерные Playwright-тесты не входят в CI; production PostgreSQL и реальные антивирус/OCR в этой среде не запускались.
